# E2E010: Forgotten `.only`

| ESLint name             | Severity | Category    | Confidence | Source | Presets     |
| ----------------------- | -------- | ----------- | ---------- | ------ | ----------- |
| `atium/no-focused-test` | error    | reliability | high       | rule   | recommended |

The values come from the rule catalogue (03-linter.md §11.8).

## What it detects

A test or describe declared with `.only`: `test.only`, `test.describe.only` (also `.serial.only` and `.parallel.only`) in Playwright, and `it.only`, `describe.only` and `context.only` in Mocha and Cypress. The bracket form `test["only"]`, the optional chain `test?.only` and the TypeScript `test.only!` count too. Other modifiers, such as `.skip` or `.fixme`, are not reported. A declaration whose callback is not a function literal, such as `describe.only("cart", sharedSuite)`, is not reported either, because without the function the rule cannot tell it is a test declaration.

## Why it is a problem

`.only` makes the runner execute only the focused tests and skip every other test of the file, or of the whole run, without failing. A `.only` left behind after debugging turns a full suite into a few tests while CI stays green, so regressions in the skipped tests go unnoticed. Playwright's `forbidOnly` catches it only when enabled, and only at run time.

## Examples

### Incorrect

```ts
test.only("adds an item to the cart", async ({ page }) => {
  await page.getByRole("button", { name: "Add to cart" }).click();
  await expect(page.getByTestId("cart-count")).toHaveText("1");
});
```

### Correct

```ts
test("adds an item to the cart", async ({ page }) => {
  await page.getByRole("button", { name: "Add to cart" }).click();
  await expect(page.getByTestId("cart-count")).toHaveText("1");
});
```

The rule offers a suggestion that removes `.only`. It is not an autofix, because removing it changes which tests run.

## Options

This rule has no options.

## When to disable it

Focusing a test is useful while debugging on your machine, but it should never reach a commit. There is no reasonable case for disabling the rule in a shared config; to focus a test locally, run it by name or line instead (`npx playwright test cart.spec.ts:12`). If you must, disable it for one line with `// eslint-disable-next-line atium/no-focused-test`.
