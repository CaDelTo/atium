# E2E003: Positional XPath

| ESLint name                 | Severity | Category  | Confidence | Source | Presets     |
| --------------------------- | -------- | --------- | ---------- | ------ | ----------- |
| `atium/no-positional-xpath` | warning  | selectors | high       | rule   | recommended |

The values come from the rule catalogue (03-linter.md §11.8).

## What it detects

An XPath selector, in Playwright's `locator()` or `$()` or in `cy.xpath()` from the cypress-xpath plugin, that:

- picks elements by position, with a predicate such as `[2]`, `[last()]` or `[position()=1]`;
- or starts at the root of the document, such as `/html/body/div`.

Playwright reads a selector as XPath when it starts with `xpath=`, `/`, `(` or `..`; the argument of `cy.xpath()` is always XPath. Each selector gives one finding, for its first reason in that order. Text between quotes is not read as a predicate, so `//a[@title='[2]']` is not reported.

It does not report XPath by attribute, such as `//button[@data-testid='x']`, CSS selectors (that is E2E002), XPath in `cy.get()`, which reads CSS, a chain such as `//a >> nth=1`, or a selector in a variable.

## Why it is a problem

A position or a full path from the root encodes how the page is built today. A new row, a wrapper element or a reordered list moves the element, and the test fails, or worse, acts on a different element. Selecting by an attribute, role, label, text or test id keeps working when the layout changes.

## Examples

### Incorrect

```ts
await page.locator("//table/tbody/tr[2]/td[3]").click();
await page.locator("/html/body/div/form/button").click();
cy.xpath("(//li)[last()]").should("be.visible");
```

### Correct

```ts
await page.getByRole("row", { name: "Order 1042" }).getByRole("button").click();
await page.locator("//form//button[@data-testid='submit']").click();
cy.xpath("//li[@data-cy='last-item']").should("be.visible");
```

The rule has no autofix or suggestion, because only you know which attribute identifies the element.

## Options

This rule has no options.

## When to disable it

When the position is the point of the test, such as checking the order of a sorted list, prefer reading all items and asserting on their order. If you must select by position, disable it for that line with `// eslint-disable-next-line atium/no-positional-xpath` and say why in the comment.
