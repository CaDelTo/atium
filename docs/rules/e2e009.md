# E2E009: Assertion that is not web-first

| ESLint name                        | Severity | Category   | Confidence | Source | Presets     |
| ---------------------------------- | -------- | ---------- | ---------- | ------ | ----------- |
| `atium/prefer-web-first-assertion` | warning  | assertions | high       | rule   | recommended |

The values come from the rule catalogue (03-linter.md §11.8).

## What it detects

An `expect(…)` or `expect.soft(…)` whose first argument awaits `isVisible()`, `textContent()` or `count()`, with any matcher or none:

```ts
expect(await page.getByRole("alert").isVisible()).toBe(true);
```

It does not report a value stored in a variable first, `expect.poll`, other methods such as `innerText()`, `inputValue()` or `getAttribute()`, the query without `await`, or Cypress, whose commands are not awaited and whose `.should()` already retries.

## Why it is a problem

`await x.isVisible()` reads the page once, at that moment. If the element appears a few milliseconds later, the assertion has already failed, and the test is flaky. A web-first assertion such as `await expect(x).toBeVisible()` waits and retries until the condition holds or the timeout runs out.

## Examples

### Incorrect

```ts
expect(await page.getByRole("alert").isVisible()).toBe(true);
expect(await page.locator(".cart li").count()).toBe(3);
expect(await page.getByRole("heading").textContent()).toBe("Home");
```

### Correct

```ts
await expect(page.getByRole("alert")).toBeVisible();
await expect(page.locator(".cart li")).toHaveCount(3);
await expect(page.getByRole("heading")).toHaveText("Home");
```

The rule replaces the assertion as follows. It keeps `.not`, `expect.soft` and the message argument of `expect`, and adds `await` when it is missing.

| Query | Matcher | Replacement |
| --- | --- | --- |
| `isVisible()` | `toBe(true)`, `toEqual(true)`, `toBeTruthy()` | `toBeVisible()` |
| `isVisible()` | `toBe(false)`, `toEqual(false)`, `toBeFalsy()` | `toBeHidden()` |
| `count()` | `toBe(n)`, `toEqual(n)` | `toHaveCount(n)` |
| `textContent()` | `toBe(s)`, `toEqual(s)` | `toHaveText(s)` |
| `textContent()` | `toContain(s)` | `toContainText(s)` |
| `textContent()` | `toMatch(re)` | `toHaveText(re)` |

- **Autofix:** the `isVisible()` and `count()` rows, when the value is read from a Playwright locator the rule recognizes: `locator()` or `getBy*`, or `.nth()`, `.first()` or `.last()` on one.
- **Suggestion:** the `textContent()` rows, because `toHaveText()` normalizes whitespace and `textContent()` may be `null`, and the other rows on any other value, such as a variable or `page.$()`, which returns an ElementHandle that web-first assertions do not accept.
- **Neither:** another matcher, arguments in the query (`page.isVisible("#a")`), a different number of matcher arguments, or comments inside the code that would be replaced.

## Options

This rule has no options.

## When to disable it

When you need the value at one exact moment, such as checking that an element is not visible yet before an action, read it into a variable first and assert on that, or disable the rule for that line with `// eslint-disable-next-line atium/prefer-web-first-assertion` and say why in the comment.
