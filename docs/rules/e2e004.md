# E2E004: Positional locator

| ESLint name                   | Severity | Category  | Confidence | Source | Presets |
| ----------------------------- | -------- | --------- | ---------- | ------ | ------- |
| `atium/no-positional-locator` | warning  | selectors | medium     | rule   | strict  |

The values come from the rule catalogue (03-linter.md §11.8).

## What it detects

A locator narrowed to one element by its position:

- `.nth(n)` with a number `n` of `minIndex` or more (by default any `n > 0`), and Cypress's `.eq(n)` on a `cy` chain;
- `.first()`, `.last()`, or `.nth()` / `.eq()` with a negative number, which counts from the end, on a locator that may match several elements.

A locator counts as unique, so `.first()` and `.last()` on it are not reported, when it is a `getByRole` with the `name` option or a `getByTestId`. Any other locator, such as `locator()`, `$()`, `getByText`, a `getByRole` without `name`, `cy.get()` or `cy.xpath()`, may match several. The rule looks for that locator earlier in the same chain, also across calls such as `.filter()`.

It does not report `.nth()` on a `getByRole` with a name, `.nth(0)` with the default options, an index that is not an integer literal (`.nth(i)`, `.nth(1.5)`), `.eq()` outside a `cy` chain, or a chain that starts from a variable, such as `items.first()`, whose locator it cannot see.

## Why it is a problem

A position encodes the order of the page today. A new row, a filtered list or a reordered menu moves the element, and the test fails, or worse, acts on a different element. `.first()` on a locator that matches several elements hides that the locator is ambiguous. Narrowing the locator by role and name, text or test id keeps working when the order changes.

## Examples

### Incorrect

```ts
await page.getByRole("listitem").nth(2).click();
await page.locator(".cart li").first().click();
cy.get("tr").eq(1).should("contain", "Ada");
```

### Correct

```ts
await page.getByRole("listitem").filter({ hasText: "Ada" }).click();
await page.getByRole("button", { name: "Remove" }).nth(1).click();
cy.get("[data-cy=row-ada]").should("contain", "Ada");
```

The rule has no autofix or suggestion, because only you know what identifies the element.

## Options

- `minIndex` (integer, at least 0, default `1`): `.nth(n)` and `.eq(n)` are reported when `n` is this or more. A negative index is reported like `.last()`, whatever `minIndex` is.

```js
"atium/no-positional-locator": ["warn", { minIndex: 2 }]
```

## When to disable it

When the position is the point of the test, such as checking the order of a sorted list, prefer reading all items and asserting on their order. If you must select by position, disable it for that line with `// eslint-disable-next-line atium/no-positional-locator` and say why in the comment.
