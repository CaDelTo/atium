# E2E002: Fragile CSS selector

| ESLint name                     | Severity | Category  | Confidence | Source | Presets     |
| ------------------------------- | -------- | --------- | ---------- | ------ | ----------- |
| `atium/no-fragile-css-selector` | warning  | selectors | medium     | rule   | recommended |

The values come from the rule catalogue (03-linter.md §11.8).

## What it detects

A CSS selector, in Playwright's `locator()` or `$()` or in Cypress's `cy.get()`, that depends on how the page is built rather than on what the user sees:

- a positional pseudo-class, `:nth-child()` or `:nth-of-type()`;
- `depth` or more combinators (3 by default), such as `div > ul > li > a`; in a list, the item with the most counts;
- a class generated by a CSS-in-JS library: Emotion's `css-1a2b3c`, styled-components' `sc-…` or styled-jsx's `jsx-123456`;
- an id with three or more digits in a row, such as `#ember123`.

Each selector gives one finding, for its first reason in that order. Only selectors written as a string literal, or a template without `${}`, are read. It does not report `getBy*` locators, XPath (that is E2E003), other Playwright engines such as `text=`, Cypress aliases such as `@user`, or a selector in a variable.

In a file of `pageObjectDirs` (a `settings.atium` key), a selector is reported only where it first appears in the file, so a Page Object that writes the same selector several times gives one finding. Specs that use the Page Object (`loginPage.submit.click()`) do not contain the selector, so they give none. A `// eslint-disable-next-line` on that first appearance also hides the later ones in the same file.

## Why it is a problem

These selectors break when the markup changes but the page does not: a new sibling shifts `:nth-child(2)`, a wrapper `div` breaks a long chain of combinators, and generated classes and ids change between builds or runs. The test then fails for a reason the user would never notice. Selectors by role, label, text or test id survive those changes.

## Examples

### Incorrect

```ts
await page.locator("div.checkout > ul > li:nth-child(2) > button").click();
await page.locator(".css-1a2b3c").fill("ana@example.com");
cy.get("#ember123").click();
```

### Correct

```ts
await page.getByRole("button", { name: "Pay" }).click();
await page.getByLabel("Email").fill("ana@example.com");
cy.get("[data-cy=submit]").click();
```

The rule has no autofix or suggestion, because only you know which stable attribute or role identifies the element.

## Options

- `depth` (integer, at least 1, default `3`): a selector with this many combinators or more is reported.

```js
"atium/no-fragile-css-selector": ["warn", { depth: 4 }]
```

It also reads `settings.atium.pageObjectDirs`: globs, relative to the directory ESLint runs from, of the Page Object code. `*` does not cross `/`, matching is case-sensitive, a leading `./` is ignored, and a path without wildcards (`tests/pages`) covers everything inside it.

## When to disable it

When the page offers nothing stable to select, such as a third-party widget without roles, labels or test ids, and you cannot add them. Disable it for that line with `// eslint-disable-next-line atium/no-fragile-css-selector`, and prefer keeping the selector in a Page Object so it lives in one place.
